Q1 – Constructors and Constructor Overloading 6 Marks 
Bloom’s Level: K5 – Evaluate 
Problem Context – Library Book Records 
A library creates Book objects in several situations: a new book with full details, a donated  book with only a title, and an empty record that will be filled later. Some records were  created with garbage values in the number of copies. 
Implementation Tasks 
You must: 
• Write a default constructor, a parameterised constructor and overloaded constructors  for the three situations 
• Use a member initializer list in every constructor 
• Use constructor delegation to avoid repeating code 
• Show that no Book can be created with an invalid number of copies 
Design & Analysis 
You must: 
• Explain when the compiler supplies a default constructor and when it does not 
• Explain why member initializer lists are preferred to assignment inside the constructor  body 
• Explain the order in which members are initialised (declaration order, not list order) • Draw the state of three objects after construction
Experimental Investigation 
You must: 
• Create Book objects with every constructor and print them 
• Remove the default constructor and record the compiler error when an array of Books  is created 
• Demonstrate a member initialised in the wrong order and the -Wreorder warning • Test a negative number of copies 
Design Question 
When should a constructor be marked explicit? Show a call that compiles without explicit  and fails with it. 
Alternative Concept and Complexity Analysis 
If one constructor with default arguments (Book(std::string t = "", int copies = 0, …)) were  used instead of several overloaded constructors and delegation, what would the solution be?  Analyse the time and space of object creation (O(1) in both) and compare which design  checks the number of copies in fewer places.
